title: "Quickstart"
description: "Run your first script through the WebSocket command channel."
---

A typical Reforged session has four steps: prepare the host, load it into the target process, connect to the local command server, and execute a script.

<Steps>
  <Step title="Prepare the host">

    Use the supplied Reforged release package for your environment. The host component is loaded into the target process and exposes the script runtime.

  </Step>
  <Step title="Load Reforged">

    Load the host component into the running game process. After startup, Reforged initializes the runtime services and starts the command server on `127.0.0.1:27015`.

    Host console output is also broadcast to connected WebSocket clients.

  </Step>
  <Step title="Connect a WebSocket client">

    Connect to `ws://127.0.0.1:27015`. The server responds with:

    ```json
    { "type": "hello", "version": "1.0" }
    ```

    Any standard WebSocket client can connect, including `wscat`, a small Python client, or a custom GUI.

  </Step>
  <Step title="Execute a script">

    Create a directory containing one or more `.c` or `.ec` files. The entry class must define `void Run();`. Example:

    ```enforce
    // C:\scripts\hello\Hello.c
    class Hello {
        void Run() {
            Console.Log("hello from a script");
            Console.Log("players = " + Memory.ReadInt(Memory.GameBase() + 0x1234));
        }
    }
    ```

    Send an execute command from the client:

    ```json
    { "type": "execute", "dir": "C:\\scripts\\hello", "class": "Hello", "entry": "Run" }
    ```

    The host stages the runtime prelude, loads the `.c` and `.ec` files from the directory, compiles the script, binds native calls, instantiates the class, and calls the entry method.

    A successful execution returns:

    ```json
    { "type": "result", "ok": true, "message": "executed" }
    ```

  </Step>
</Steps>

## Debugging

- The host console shows every log line.
- The mirror log file captures the same output for offline review.
- WebSocket errors use the result format: `{"type":"result","ok":false,"message":"..."}`.
